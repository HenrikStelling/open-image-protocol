# OEP-002 ablation — low-confidence spacing guard (NIH-50, Ollama models)

Started 2026-09-29 12:00. Harness commit dd5e7a2 (+ readout-time additions), scorer 0.3. Packages `~/oip-bench/nih-paper`,
seed 0, 50 images, tasks `ctr` (±0.05), `heart_mm` (±10 %), `left_edge`; 600 calls per model. Lanes: cloud
(glm-5.3-flash → gemma4:31b → kimi-k3 → minimax-m3 → mistral-large-3, one at a time through `bench/cloudlock.py`) and
local (gemma4:e4b-it-qat, medgemma1.5:4b). Readout script: session scratchpad `oep2_report.py` (Wilson CIs, exact McNemar
on paired items against `ctx_l1_ctl`, and the same restricted to items where both replies are complete).

## Conditions

| condition | prompt |
|---|---|
| `raw_ctl` | image only (same-day control for the paper's `raw`) |
| `ctx_l1_ctl` | image + L0–L2 file as shipped (spacing stated with confidence `low`, no measurements) |
| `ctx_l1_oep2` | as above + guard: "LOW-CONFIDENCE SCALE … do NOT derive sizes in millimetres from it yourself" and self-check item 3 rewritten (`build_context(low_confidence_guard=True)`) |
| `ctx_l1_oep2e` | guard + estimation caution: "Estimating from the image: … do not compute it from pixel coordinates you estimate yourself" (`estimation_caution=True`) |

Intended behaviour under the guard: `heart_mm` answered in pixels or declined (scored as abstention), `ctr` unchanged or
recovered towards `raw_ctl` (the paper found L0–L2 lowers CTR on NIH for gpt 57→42 and glm 61→43 because the models
compute from their own pixel estimates), `left_edge` unchanged.

"truncated" = the reply has no closing `</think>` and `output_tokens` reached the 800-token cap (`num_predict`), i.e. the
model was cut off inside its reasoning and the scorer read a number out of the truncated text (8/50 `heart_mm` values in
`ctx_l1_oep2` are > 300 "mm", pixel widths taken as millimetres).

Readings:
- **The guard does not change what glm does; it changes what it says.** All 50 guarded `heart_mm` replies acknowledge
  the low-confidence scale ("nominal", "uncalibrated", "low-confidence"), and then multiply their pixel estimate by the
  nominal spacing anyway ("≈140 mm … this uses the nominal horizontal spacing of 0.3985 mm/px"). Zero abstentions in
  every arm. Accuracy 22 → 16 %, n.s.
- **The estimation caution recovers CTR** (26 → 50 %, discordant pairs 5/17, p = 0.017; on complete pairs 35 → 61 %,
  p = 0.057) — above `raw_ctl` (38 %), i.e. back to what glm's `ctx` cells with measurements did not need. The guard
  alone does not (32 %).
- Left edge unchanged (86–92 %, n.s.).
- **Truncation confound.** glm reasons visibly inside `content` even with `think=false` and closes with `</think>`; at
  `num_predict` 800 the reasoning is cut off before the answer in 17/50 (`ctr`, `ctx_l1_ctl`) to 30/50 (`heart_mm`,
  `ctx_l1_oep2`) replies. The L0–L2 file lengthens the reasoning (px→mm arithmetic), so truncation is itself part of the
  L0–L2 effect, but a truncated reply measures the output cap, not the model's answer. The same holds for the paper runs
  (below). Fix implemented in `bench/run.py`: `--ollama-think on|auto` sends `think=true` (the daemon then returns the
  reasoning in `message.thinking`, verified with a two-call probe: same 39 tokens, content = answer only), stores it as
  `<think>…</think>` in front of the answer so the scorer's tail rule is unchanged, and every row's `usage` now records
  `done_reason` ("length" = cap hit), `num_predict`, `think` and `thinking_chars`. Default stays `off` until the running
  lanes finish, so all seven OEP-002 models share one setting.

Readings: gemma4:31b has no L0–L2 drop to repair (CTR 62 → 58 %, heart width 48 → 52 %, n.s.), and the guard costs it
all 26 heart-width answers that were within 10 % ("No calibrated scale is available." in 50/50, no pixel answer). The
estimation caution is neutral on CTR. This is the cost side of the guard: a model that uses the stated spacing correctly
is told to stop.

**What the `heart_mm` endpoint can and cannot say here.** The NIH heart-width truth is the segmentation width times the
same dataset-derived nominal spacing the file states, so "correct" means "consistent with the nominal spacing", not
"true millimetres". A model that multiplies its pixel estimate by the stated spacing agrees with the truth whenever its
pixel estimate is good (gemma4:31b 52 %, glm's complete replies 36–40 %); the guard forbids exactly that computation.
The endpoint therefore measures compliance (abstention rate) and the accuracy loss, not whether abstaining is the
better clinical answer; that question needs the calibrated-spacing subset or Tier-2 truth (PLAN: NIH heart_mm ground
truth item). The CTR endpoint is unaffected by this, because CTR is a ratio.

## Decision (D-031, decisions log)

1. **Estimation caution adopted** as template 0.2.1: one sentence in "How to read", on by default in `build_context`. It
   repairs the L0–L2 CTR drop wherever the drop occurs (three of three models, two of them fully, back to or above the
   image-only level) and moves nothing on the four models without a drop, on heart width or on the left-edge question. No
   single model survives Holm over seven at n = 50; the adoption rests on the consistent direction, the absence of any
   cost, and the mechanism (the CTR replies stop citing pixel coordinates: minimax 10 → 0). Confirmation planned on
   gpt-5.6-terra, the model with the paper's NIH drop (57 → 42 %), 600 calls ≈ $3, as the pre-specified repeat.
2. **Low-confidence guard not adopted.** It never improves a measurable endpoint; three models comply fully and lose every
   correct heart width (gemma4:31b −26, mistral −15, e4b −5 of 50), three comply partly and lose accuracy without
   abstaining (minimax −12, kimi −8, MedGemma), one acknowledges it in every reply and computes anyway (glm). The flag
   stays in the code for reference (`low_confidence_guard=True`), off.
3. **Endpoint caveat carried into PLAN:** the NIH heart-width truth uses the same nominal spacing the file states, so
   the guard's premise ("the nominal spacing yields wrong millimetres") cannot be tested on NIH; the calibrated subset or
   Tier-2 truth is needed before a guard of this kind is measured again.
4. The harness keeps the 0.2 wording for every legacy condition (`run._ctx(est=False)`), so paper cells and the paused
   Claude OEP-004 arm remain reproducible; round-3 conditions should render the shipped template (`est=None`).
