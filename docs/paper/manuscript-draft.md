## Abstract

Vision-language models are usually shown medical images as 8-bit exports that have silently lost units, pixel spacing, orientation and polarity, and they are then asked questions whose answers depend on exactly that information. We describe the Open Image Protocol (OIP), a self-describing package format for one medical image: a schema-validated manifest, model-ready renders, deterministic measurements with provenance, and a fixed-template natural-language reference file in which every statement carries an assertion level. Measurements are computed by tools, never by the model, and the package contains no diagnostic logic. We evaluate OIP with OIP-Bench, which asks eleven vision-language models (three frontier APIs, six open cloud models and two small local models) understanding questions about 100 VinDr-CXR radiographs, 50 NIH ChestX-ray14 radiographs and 40 whole-body bone scans under six input conditions, using 60,483 frozen replies. On the gating tasks (side at the image's left edge, availability of a calibrated scale, cardiothoracic ratio within 0.05, cardiac width within 10 %), accuracy with the image alone ranged from 36 to 65 % on VinDr-CXR and from 17 to 74 % on NIH; with the full package it was 100 % for nine of eleven models on VinDr-CXR and 99–100 % for nine of eleven on NIH (exact McNemar p < 0.001 after Holm correction for every model on both sets), and the spread between models fell from 11.1 to 3.9 percentage points. A layer ablation attributes roughly half of the gain to geometry, units and orientation and the rest to the computed measurements; on NIH, whose spacing is low-confidence, the geometry layer alone helped no model and hurt two. Three findings differentiate models where the main result does not: only Gemini 3.8 Flash, GPT-5.6 Terra and GLM-5.3 Flash reliably detect a mirrored render that contradicts the stated orientation, the remaining eight models scoring between 50 and 63 %; a wrong prior-report label delivered through the shipped template instead of as a bare note reduced its adoption significantly for eight of eleven models, by amounts from 11 to 93 percentage points, and not for Gemini, Kimi K3 and Mistral Large 3; and on bone scans every model identified the tracer-hotter side at chance. Understanding a medical image is, to a large degree, a data-format problem before it is a model problem. The specification, converter, benchmark harness, package manifests and all replies are released.

## 1. Introduction

Vision-language models (VLMs) answer questions about medical images fluently, and their clinical reasoning is often correct once the facts about the image are correct. The facts are the problem. Benchmarks of quantitative perception show that foundation VLMs estimate sizes, distances and angles poorly [1]; a dedicated study of laterality found that models confuse the patient's left with the image's left even when the film carries a printed marker [2]; and when a text context accompanies the image, models adopt it at high rates whether or not the pixels support it [3]. These are not reasoning failures. They are failures to know what a pixel is worth in millimetres, which way the patient is facing, and how much a sentence in the prompt should be trusted.

Today's pipelines make all three failures likely. A DICOM object carries pixel spacing, orientation, photometric interpretation, bit depth and the display window [4], but the model never sees the DICOM object. It sees an 8-bit PNG or JPEG produced by a conversion step that discards the spacing, may flip the polarity of a MONOCHROME1 image, resamples without updating the spacing, and drops the orientation with the header. The choice of window alone changes what a model can read [5]. In Section 5 we quantify what four widely used public chest-radiograph sources actually deliver after this step: one source retains a trustworthy absolute scale for 82 % of its images, two carry a pixel spacing that is stale after resampling for 100 % of theirs, and one has no header at all.

Other fields have solved a structurally similar problem, that of making a foreign system readable to a model without retraining the model. The Language Server Protocol made every programming language available to every editor through a neutral abstraction, text documents and positions, and a small verb set [6]. The Model Context Protocol lets an assistant use any tool or data source through a schema plus prose self-description and a discovery step [7]. The Model Hardware Standard makes physical devices readable by generating a reference file for the model while keeping safety limits in the driver rather than in the model [8]. None of them translates the foreign system at run time; each forces it to describe itself in advance in a vocabulary the model already reads.

We apply that pattern to medical images. The Open Image Protocol (OIP) defines a package for one image with a schema-validated manifest, a natural-language reference file generated from it by a fixed template, model-ready renders with correct polarity and orientation marks, lossless pixels, and measurements computed by deterministic tools. Every fact carries an assertion level (measured, computed, inferred, external, unknown). The package carries observations and, optionally, cited reference ranges, but no findings, impressions or diagnostic rules.

The paper makes five contributions. First, the protocol and the ten design rules from which it follows (Section 3). Second, a reference implementation that converts DICOM and, with reduced fidelity, PNG-plus-metadata sources for projection radiography and planar scintigraphy, with the record of what 2,100 public images actually contained (Section 4). Third, OIP-Bench, a benchmark of understanding tasks whose answers are not in the reference file verbatim, with a layer ablation, a render-consistency test and a misleading-text test (Section 5). Fourth, the empirical results on eleven models, three datasets and two modalities, including a benchmark-driven revision of the specification (Sections 6 and 7). Fifth, an open release of the specification, code, package manifests and every model reply.

## 2. Related work

**Standards for imaging AI.** DICOM Structured Reporting with template TID 1500, implemented by highdicom [9], the IHE AI Results profile [10], FHIR ImagingStudy [11] and the RSNA common data elements [12] describe the outputs of AI for clinical systems. They are not designed as inputs for a model, they carry no natural-language layer and they do not define renders. NIfTI with BIDS sidecars [13] and OME-Zarr [14] define sidecar conventions for research data; OIP borrows the sidecar idea and the explicit orientation semantics but adds the model-facing layers. The llms.txt convention [15] is the closest analogue to OIP's reference file: prose written for a model, generated from structured data.

**Prompting VLMs with visual and textual scaffolds.** Set-of-Mark prompting [16] and grid or ruler overlays [17] improve grounding by putting labels into the pixels; OIP's annotated render is a constrained instance with edge labels, a scale bar and numbered region marks whose coordinates are stated in the manifest. The MC-CXR study [3] measured how much a text context disrupts chest-radiograph interpretation; our misleading-text condition reproduces its recipe and asks whether a labelled, cautioned delivery changes the outcome. MedVision [1] and the laterality study [2] provide the task families that OIP-Bench's gating tasks target.

**Medical VLMs.** CXR-LLaVA [18], LLaVA-Rad [19], MAIRA-2 [20] and MedGemma [21] are trained on radiographs and reports. OIP is orthogonal: it changes the input, not the model, and we include a MedGemma model to show that domain training does not by itself supply the geometric facts. A DICOM MCP server [22] exposes archive queries to an assistant; OIP defines what a single image should look like when it arrives.

## 3. The Open Image Protocol

### 3.1 Design rules

The protocol follows ten rules derived from the comparison of LSP, MCP and the Model Hardware Standard. R1, a neutral core: every package has geometry in millimetres, orientation, intensity units and provenance, whatever the modality. R2, self-describing twice: machine-readable (`oip.json`, JSON Schema) and model-readable (`context.md`, fixed template). R3, a small verb set. R4, physics and safety live in the tool layer, not in the model. R5, an assertion level on every fact. R6, conformance profiles so partial producers remain useful. R7, semantic versioning, a deprecation policy and a change process with proposals (OEPs). R8, stateless packages: everything needed to interpret the image is inside. R9, ship the bundle: specification, SDK, CLI, MCP server, examples and benchmark together. R10, measure uplift: every protocol change is evaluated on the benchmark before it enters the specification.

### 3.2 Package layout, layers and profiles

A package is a directory `<name>.oip/` (or a zip of it) with a manifest `oip.json`, the reference file `context.md`, a canonical 8-bit render, an annotated render, lossless 16-bit PNG pixels per frame, optional derived measurements and masks, and the de-identified DICOM headers as a DICOM JSON model. The manifest is organised in six layers: L0 identity, provenance and de-identification; L1 acquisition, geometry, intensity semantics and quality flags; L2 renders and pixels; L3 semantic regions; L4 measurements; L5 narrative and external context. Profiles are named layer sets (`core` = L0–L2, `measured` = L0–L4, `full` = L0–L5); a producer must declare its profile and must not claim a layer it did not fill. Manifest rules make the guardrails explicit: pixel spacing must be null unless a spacing with a stated source exists, and a consumer must not infer physical size when it is null; the calibration plane distinguishes detector-plane from patient-plane spacing; counts are comparable only within one package and energy window; identifiers, names, dates and free text are removed or hashed, and age is reduced to a five-year band.

### 3.3 The reference file

`context.md` is generated from the manifest by a fixed template (version 0.2 in this paper) with nine sections in fixed order: what this is; how to read the renders; measured facts; computed measurements; inferred; unknowns and cautions; external context; self-check; machine-readable. Each statement in the factual sections is prefixed with its assertion level in brackets. The "how to read the renders" section states the polarity guarantee (higher attenuation or higher counts is brighter in the canonical render), the anatomical side at each image edge, the pixel spacing with its source, plane and confidence, or the sentence "NO pixel spacing is available. Do not state sizes in mm or cm", and the window used. The self-check section lists four question-and-answer pairs whose answers are in the package (which side is at the left edge, the modality, whether sizes can be given in millimetres, and the polarity) so that a model can calibrate before answering. External content, such as dataset labels or prior-report text, is not rendered by default; when a consumer requests it, the cautions precede it and it is introduced as unverified. Section 7 describes the benchmark result that produced this rule. The file is about 3,300–3,600 characters, roughly 830–890 tokens, for a chest radiograph.

### 3.4 Renders

The canonical render is an 8-bit greyscale image with the frame's rows and columns, no rotation, flip, crop or resampling, polarity high-is-bright, and the source display window when present or robust percentiles otherwise; the exact transform is recorded. The annotated render adds a letterbox margin with edge labels giving the anatomical side of each edge, a scale bar with its length in millimetres or the text "no calibrated scale", optional numbered region marks listed in the manifest, and a modality-and-view title; the image area stays pixel-aligned with the canonical render so that coordinates in the manifest remain valid after subtracting the stated margins. Scintigraphy packages should also carry an inverted render, because hot-is-dark is the conventional display.

### 3.5 Measurements as tool outputs

Measurements live in `derived/measurements.json` with an identifier, name, value, unit, method, confidence and validation status, and are computed by deterministic tools. The `measure` verb refuses to return millimetres when spacing is null and refuses to compare counts across energy windows. For chest radiographs the reference implementation computes anatomical regions with a segmentation model and derives the transverse cardiac diameter, the thoracic width and the cardiothoracic ratio (CTR). The validation status of every value is `unvalidated` until a tiered validation has been run: Tier 0 on synthetic phantoms with exact truth, Tier 1 plausibility rules and cross-tool checks, Tier 2 against reference masks, Tier 3 against expert readings.

### 3.6 Modality adapters

The reference converter handles DICOM projection radiography (CR, DX), single-frame CT and MR, and multi-frame nuclear-medicine objects, and has a non-DICOM path for PNG or JPEG images accompanied by dataset metadata, which are marked with the `external` assertion level and a low spacing confidence. For planar scintigraphy the adapter records tracer, activity, uptake time, energy windows and per-frame counts when available, renders with a square-root window, and, for sources that ship stretched 8-bit PNGs, recovers the count quantisation lattice where possible (Section 4).

### 3.7 Access paths and scope

The same verbs (`describe`, `locate`, `measure`, `window`, `crop`, `overlay`, `validate`) are exposed by a Python SDK, a CLI and an MCP server. None of them is required: to hand an image to a model, one sends a render and `context.md`. By design the protocol carries observations and optional cited reference ranges and never interpretations; findings, impressions and diagnoses are produced by the consuming model or a downstream tool, and detector outputs may be carried only as `inferred` observations with the producing tool named.

## 4. Reference implementation and real-data conversion

We converted 2,100 images from four public sources with the reference converter: 1,000 VinDr-CXR DICOM files [23], 500 RSNA Pneumonia and 300 SIIM-ACR Pneumothorax DICOM files, and 300 NIH ChestX-ray14 PNG files [24]. There were no failures. Table 1 summarises what the sources contained.

**Table 1. What four public chest-radiograph sources deliver to a converter.** Counts are images.

| Source | n | Format | Pixel spacing | Spacing confidence | Polarity / depth | Window in source | Orientation in header |
|---|---|---|---|---|---|---|---|
| VinDr-CXR | 1,000 | DICOM (550 implicit VR, 378 JPEG 2000 lossless, 72 explicit VR) | PixelSpacing tag in 815; none in 185 | medium 809, low 6, none 185 | MONOCHROME1 216, MONOCHROME2 784; 10–16 bits | window in 964 | none (inferred from view in 1,000) |
| RSNA Pneumonia | 500 | DICOM, 8-bit lossy JPEG baseline | PixelSpacing tag in 500, stale after resampling (computed image width 142–199 mm) | low 500; implausible extent flagged in 500 | MONOCHROME2; 8 bits | none | none (inferred) |
| SIIM-ACR | 300 | DICOM, 8-bit lossy JPEG baseline | as RSNA (stale) | low 300; implausible extent in 300 | MONOCHROME2; 8 bits | none | none (inferred) |
| NIH ChestX-ray14 | 300 | PNG | from dataset documentation | low 300 | 8 bits | none (full range) | none (inferred) |

Only VinDr-CXR retains a trustworthy absolute scale, for 82 % of its images; a fifth of its images are stored inverted (MONOCHROME1) and would be rendered with the wrong polarity by a naive export. The RSNA and SIIM files carry a pixel-spacing tag that no longer matches the resampled 8-bit pixels, so a converter that trusts the tag produces an image width of about 15 cm for an adult thorax; the converter's plausibility rule flagged every one of them. The orientation was inferred from the view in every image of every source, which is why the left-edge truth in the benchmark rests on a laterality check rather than on a header (Section 5.6). The converted package is 1.23 times the size of the DICOM source for VinDr-CXR, and the reference file costs about 830–890 tokens.

On the 1,000 VinDr-CXR images the anatomy adapter, a PSPNet from TorchXRayVision [26], produced on average 13 regions per image and a CTR for every image (median 0.478, 10th–90th percentile 0.415–0.553), with a transverse cardiac diameter for the 815 images with calibrated spacing (median 128 mm) and a refusal for the 185 without. The CTR exceeded 0.50 in 34 % of images, about twice the dataset's cardiomegaly label prevalence, because the union of the lung fields underestimates the internal thoracic width; the measurement is therefore biased high and its validation status remains `unvalidated` pending Tier 2. A laterality sanity check (a structure labelled left or right found on the wrong image side) flagged 0 of 1,000 images.

For scintigraphy we used the Paraguay whole-body bone-scan collection [25], 582 16-bit PNG images of 256 × 1024 pixels in anterior and posterior pairs. Count recovery from the quantisation lattice succeeded for 71 % of images; the rest carry stretched values with the `counts_not_comparable` flag.

## 5. OIP-Bench

### 5.1 Data

Three package sets were built for the paper, all with the no-leakage rule: no radiologist box, finding label or report text enters any package, and a keyword check runs after generation. The VinDr-CXR set holds 100 images sampled with seed 1 (the sampling script's default; a re-run of the selection rule reproduces the set only with this seed) and stratified by findings, cardiomegaly label and spacing availability; 82 of them have calibrated spacing. The NIH set holds 50 images (seed 1) converted through the non-DICOM path, so their spacing is dataset-derived and low-confidence. The bone-scan set holds 40 packages, 20 anterior and 20 posterior views. A 20-image VinDr-CXR pilot set, used while the harness was developed, appears only in the descriptive wording ablation of Section 6.6.

### 5.2 Conditions

Each task was asked under up to six input conditions (Table 2). The L0–L2 condition renders the reference file from a manifest with the regions and measurements removed, so it contains identity, geometry, units, orientation and cautions but no computed values. The two misleading conditions inject one wrong finding label, drawn per image from the labels the image does not have, either as a bare "Prior report note", the way report text is pasted into prompts today, or through the shipped template's external-context section, which places it after the cautions with the unverified wording. Bone scans ran the first three conditions only.

**Table 2. Input conditions.**

| Condition | Model input |
|---|---|
| raw | canonical render only |
| L0–L2 | canonical render + reference file without computed regions and measurements |
| full | canonical render + full reference file |
| annotated | annotated render (edge labels, scale bar, numbered region marks) + full reference file |
| misled, plain | canonical render + a wrong label as a bare prior-report note |
| misled, template | canonical render + the same wrong label rendered through the shipped template |

### 5.3 Tasks

Tasks were built from each package's manifest so that the ground truth is the package's own fact. The gating tasks, which decide releases, are those whose answer cannot be read from the reference file verbatim or that require the pixels: which side of the patient is at the image's left edge; whether distances can be stated in millimetres with a known calibration; the CTR (tolerance ± 0.05 absolute); the transverse cardiac diameter in millimetres (± 10 % relative); on the annotated render, which numbered mark outlines the heart, and on which side of the patient a named mark lies (the target alternates between left- and right-sided structures by package so that the truth is balanced); and, in the reference-file conditions, whether the shown image agrees with the stated orientation or is mirrored, asked twice per image, once with the true render and once with a horizontally mirrored copy, so that a constant answer scores 50 %. Modality and view are asked but no longer gate, because every model answered them correctly from pixels alone on frontal radiographs. The finding-level tasks, listing abnormalities from the 14 VinDr-CXR classes scored by F1, are reported but do not gate, in line with the protocol's scope. On the NIH set the scale-availability task was not asked, because "yes, with low confidence" is a legitimate answer that the yes/no format cannot score. For bone scans the tasks are the modality, the side at the left edge (posterior views are displayed mirrored, so the answer differs by view), scale availability, whether brightness can be compared with another patient's scan, which patient side shows more tracer uptake (asked only on the 8 scans whose left–right count asymmetry exceeded 8 %), and the flip check.

### 5.4 Models and settings

Eleven models were run through one harness with the same system prompt (Table 3). The three frontier models were called through their official SDKs with the lowest reasoning effort each offers and a 600-token output budget (4,000 for Claude, whose reasoning is adaptive, with prompt caching on the image and reference-file blocks). The six Ollama cloud models and the two local models were called through a local Ollama daemon (version 0.33.3) with thinking off and an 800-token budget. Each (model, condition, task item) received exactly one reply; there are no repeats. The Ollama runs took place between 8 and 21 September 2026, interrupted by the provider's daily and weekly usage throttles and resumed from checkpoints without loss of rows, and the frontier runs on 21–22 September 2026. Cloud model versions are not pinned by the providers.

### 5.5 Scoring

Replies are free text and are scored by a deterministic scorer from the text alone: exact match for categorical answers with synonym lists; a number extracted in a fixed order of preference (after an explicit answer marker, then the first number on the last line, then the last number anywhere) for CTR and width, with percentages converted to ratios; F1 over the label set for findings, taking the label list from the reply's last line. A reply that states it cannot determine the answer on an answerable task, or from which no number can be extracted, is an abstention and is scored incorrect; empty replies are treated the same way. In the misleading conditions the scorer also records whether the injected label appears in the answer. Token usage, cache usage and wall-clock latency were captured per call.

### 5.6 Ground truth and its provenance

The left-edge truth comes from the converter's orientation, which is inferred from the view for every image (Table 1) and supported by the laterality check of Section 4. The scale truth comes from the manifest's spacing and calibration confidence. The CTR and cardiac-width truth is the package's own tool measurement; the benchmark therefore tests whether a model uses the package's measurements, not whether those measurements are correct, and their correctness is validated separately (Section 6.9). The heart-mark and mark-side truths come from the region marks and bounding boxes in the manifest. The hotter-side truth for bone scans is computed from the pixels by the task builder.

### 5.7 Statistics

The primary endpoint is gating accuracy on the four tasks asked in every condition (left edge, scale availability, CTR, cardiac width; three on NIH), per model and dataset, with the full reference file compared with the raw image. Cells carry Wilson 95 % confidence intervals. Condition contrasts are paired by task item and tested with the exact McNemar test on the discordant pairs, with Holm correction over the eleven models within a dataset and contrast, and Cohen's g as the effect size; b and c denote the items correct only in the baseline and only in the new condition. Flip-check, mark-side and hotter-side accuracies are tested against the 50 % chance level with an exact two-sided binomial test. The cross-model spread is the population standard deviation of the eleven model accuracies per condition, with a percentile bootstrap 95 % interval over 2,000 resamples of the task items. The pilot set, the finding-level F1, cost and latency, and the cross-tool measurement check are descriptive. The analysis plan was written after data collection and after the descriptive scoreboard had been seen; it is a post-hoc plan, fixed before the inferential code was written, and it is released with its dated amendments (`oipbench/PROTOCOL_oip.md`). Error rows (transport failures) are excluded from denominators and counted separately: 5 on the bone scans, 12 on NIH and 1 on VinDr-CXR after retries, of which four NIH items for one model remained unanswered in the L0–L2 condition.

## 6. Results

The analysis covers 60,483 replies on the three paper sets: 16,476 from the frontier models, 32,939 from the Ollama cloud models and 11,068 from the local models.

### 6.2 Layer ablation: geometry and units first, then measurements

On VinDr-CXR the L0–L2 file alone, which contains no computed value, raised gating accuracy for every model, by +11 (glm-5.3-flash) to +40 percentage points (mistral-large-3), all Holm-corrected p ≤ 0.002. Adding the regions and measurements raised it further by +13 (gemma4:31b) to +37 (gpt and medgemma), all p < 0.001. Averaged over models, roughly half of the total gain comes from the geometry layer and half from the measured layer. The per-task view (Table 5) shows what each layer supplies. The scale-availability task is answered at 16–21 % with the raw image by nine models (the two local models, which tended to answer "yes", scored 36 % and 82 %): a model cannot know from pixels whether a calibration exists and most answered "no", which is correct only for the 18 uncalibrated images; the L0–L2 file takes every model to 99–100 %. The left-edge task is answered at 99–100 % from pixels by seven models, at 87 % by glm-5.3-flash and at 58 %, 41 % and 14 % by mistral-large-3, gemma4:e4b and medgemma, and the file takes all but glm-5.3-flash (91 %) and the two local models to 99–100 %. The CTR and cardiac-width tasks are the ones the measured layer resolves: with the L0–L2 file the CTR is within 0.05 for 17–80 % of items and the cardiac width within 10 % for 12–67 %, and with the full file both are 99–100 % for every model except glm-5.3-flash (79 % and 89 %).

It raised no model's accuracy significantly (gemma4:e4b +11, mistral-large-3 +9, medgemma +9 and gemini +8 percentage points, Holm-corrected p ≥ 0.22), and it lowered two: gpt from 57 % to 42 % (25 items correct only with the raw image against 3 only with the file, p < 0.001) and glm-5.3-flash from 61 % to 43 % (48 against 22, p = 0.025). For gpt the loss is not abstention (it abstained on none of the 150 items): given the pixel spacing, it computed the cardiac width from its own pixel estimate, and 43 of its 50 estimates fell between 50 and 90 % of the reference value, whereas its raw guesses, anchored on a plausible adult prior, were within 10 % for 18 of 50. For glm-5.3-flash the estimates scattered in both directions. The measured layer then resolved both tasks for every model (+23 to +60 percentage points, all p < 0.001). A geometry layer that invites computation without the computed value can be worse than no layer, which is an argument for the `measured` profile as the default for consumers.

### 6.3 The annotated render and localisation

On the four common tasks the annotated render added nothing over the full file for any model (VinDr-CXR: 0 to +3 percentage points, no Holm-corrected p below 0.65). Its value lies in the tasks that need it. Every model but medgemma identified the numbered mark outlining the heart on 100 % of VinDr-CXR images (medgemma 95 %, 89–98); on NIH the same held (glm-5.3-flash 98 %, medgemma 68 %). The mark-side task, which asks on which side of the patient a marked structure lies while the render carries printed R and L edge labels, separated the models: 99 % (95–100) for gemini, gemma4:31b, kimi-k3 and qwen3.5 on VinDr-CXR, 88–92 % for mistral-large-3, claude, gpt and minimax-m3, 73 % (64–81) for glm-5.3-flash, 51 % (41–61, p = 0.92 against chance) for gemma4:e4b, and 28 % (20–37, p < 0.001, below chance) for medgemma, which mapped the image side to the patient side despite the labels; NIH gave the same ordering.

### 6.4 Flip consistency: do models check the pixels against the text?

### 6.5 Misleading text

Under a wrong finding label given as a bare prior-report note, the models adopted it into their answer on 45 % (qwen3.5) to 100 % (claude, glm-5.3-flash, mistral-large-3) of the 100 VinDr-CXR images, and their findings F1 collapsed to 2–40 % from 18–59 % without the note (Table 7, Figure 3). Delivering the same label through the shipped template lowered adoption significantly for eight of the eleven models: by 93 percentage points for medgemma (94 % to 1 %), 45 for minimax-m3, 31 for qwen3.5, 29 for glm-5.3-flash, 26 for gpt, 22 for gemma4:e4b, 17 for claude and 11 for gemma4:31b (Holm-corrected p ≤ 0.030). It did not change adoption for gemini (75 % to 78 %), kimi-k3 (81 % to 69 %, p = 0.20) or mistral-large-3 (100 % to 100 %). Even where the template helped, F1 under the wrong label stayed below the label-free level for every model; only medgemma and qwen3.5 came within seven points of it (45 % against 52 %, and 54 % against 59 %). A cautioned, labelled delivery is therefore a partial safeguard whose size depends on the model, which is why the protocol omits external text from the reference file by default.

### 6.6 A benchmark-driven change to the specification (OEP-001)

The template's external-context section did not start out as a safeguard. In version 0.1 the section rendered the label after the facts with the tag "[external — verify against the pixels]", and the 20-image pilot showed that this made the wrong label more credible, not less: gemma4:31b adopted it on 75 % (53–89) of images as a bare note and on 100 % (84–100) inside the v0.1 section, qwen3.5 on 25 % against 60 %, kimi-k3 on 80 % against 90 %. A labelled section inside an authoritative reference file lends credibility to whatever it contains. Proposal OEP-001 changed three things: cautions precede external content; the content is introduced as unverified, with the statement that such labels are wrong in a substantial fraction of cases and must not be repeated unless the pixels show them; and external content is omitted from the reference file by default and rendered only on explicit request. On the pilot set the revised wording brought adoption to 10 % for gemma4:31b, 0 % for minimax-m3 and qwen3.5, 40 % for kimi-k3, 60 % for glm-5.3-flash, 75 % for gemma4:e4b and 80 % for mistral-large-3 (n = 20 each). These pilot values overstate the effect measured on the 100-image set (Table 7): with five times the images, the template's adoption rates for the same models are 69 %, 42 %, 14 %, 69 %, 71 %, 75 % and 100 %. Because two capable models still adopted the label on at least 60 % of pilot images, the wording alone was judged insufficient, and omit-by-default became the rule (decision D-027, template 0.2). The 100-image result confirms that judgement.

### 6.7 Finding-level tasks

The package carries no label information, so the finding-level F1 should not rise for reasons other than better understanding, and it should not fall. Across the eleven models the F1 with the raw image was 18–59 %, and with the full file 31–58 %; the largest change was mistral-large-3 (18 % to 48 %), and medgemma moved from 52 % to 47 %. These values are descriptive and are not a gating result.

### 6.8 Planar scintigraphy

On the 40 bone scans the package resolved the questions that depend on acquisition facts and left those that depend on reading intensity against the stated orientation unresolved (Table 8, Figure 5). From pixels alone, medgemma did not recognise a bone scan as scintigraphy on any image (0 %), mistral-large-3 on 38 % and gemma4:e4b on 70 %; with the reference file every model answered 100 %. The side at the left edge of a posterior view, which is displayed mirrored, was identified with the raw image at 0 % (qwen3.5), 15 % (gemma4:31b), 50–75 % for seven models, 95 % (gpt) and 100 % (gemini); with the full file at 100 % for five models, 85–95 % for four, 80 % for claude and 60 % for minimax-m3. Scale availability went from 0–100 % to 95–100 %, and the models already knew that counts are not comparable across patients (98–100 % throughout, medgemma 82–100 %). The aggregate over the three gating tasks rose significantly for seven of the eleven models (Holm-corrected p ≤ 0.013), and not for gemini (95 % raw), gpt (92 % raw), kimi-k3 (83 % to 93 %, p = 0.090) and minimax-m3 (78 % to 86 %, p = 0.63).

The hotter-side task, asked on the 8 scans with a clear count asymmetry, was answered at 0–6 of 8 by every model in every condition, none differing from chance (all p ≥ 0.07); glm-5.3-flash answered 1, 0 and 1 of 8 in the three conditions, which is consistent with the mirrored convention but not distinguishable from chance at this n. The flip check on scintigrams was at 45–54 % for every model, including the three that passed it on radiographs. The reference file, then, supplies the facts about a scintigram but does not make a model consult the pixels against them.

### 6.9 Cost, latency and the measurement cross-check

The reference file adds about 1,000 input tokens in its L0–L2 form and about 1,400 in full, and the annotated render about 80 more (gemma4:31b: 338 tokens per raw call, 1,359 with the L0–L2 file, 1,744 with the full file, 1,827 with the annotated render). At list prices the full file raised the cost of a call from US$ 0.0009 to 0.0019 for gemini, from 0.0048 to 0.0071 for gpt and from 0.0014 to 0.0033 for claude, where cache reads and writes are included. The three frontier lanes cost US$ 8.93 (gemini), 37.19 (gpt) and 15.08 (claude) for 5,492 calls each. Median latency was 2–4 s per call for most models, 8–10 s for qwen3.5 and 4–7 s for glm-5.3-flash, whose replies carry visible reasoning (87–338 output tokens per call, and 18–87 for gpt, against 20 or fewer for most other models); these latencies include client-side back-off and are descriptive.

The cardiac width measured by the package's PSPNet adapter was cross-checked against an independent CXAS segmentation [27] on the 18 pilot images with calibrated spacing: the mean difference was +4.9 mm (CXAS minus PSPNet; SD 9.0 mm; 95 % limits of agreement −12.8 to +22.6 mm), and all 18 pairs were within the benchmark's 10 % tolerance. The thoracic-width and CTR values in the same cross-check file are not comparable, because the CXAS output there is a rib-margin internal width computed on a different basis (mean 269 mm against 356 mm for the lung-field union, with a mean CTR of 0.63), and they are not used; the CTR truth therefore remains at validation Tier 1 with the known upward bias described in Section 4.

## 7. Discussion

The main result is large and uniform: on tasks that require knowing the orientation, the scale and a calibrated measurement, every model went from a raw accuracy between 17 and 74 % to 99–100 %, with two exceptions at 84–90 %, once the package was in the prompt. The uniformity is the point. The spread between models fell from 11–17 to 4–6 percentage points, which means that most of what distinguished the models on these questions was not perception or reasoning but whether the information had reached them. That is the sense in which understanding is a data-format problem before it is a model problem, and it is what the three reference protocols would predict: LSP did not make editors smarter about languages, it made languages describe themselves.

The layer ablation refines the claim. The geometry layer, which contains no computed value, supplied about half of the gain on the calibrated set by answering the scale question outright and correcting the orientation for the models that had it wrong. The measured layer supplied the rest, and it did so by substitution rather than by assistance: a model given the CTR in a table reports the CTR in the table. The NIH result shows the failure mode of a half-measure. With low-confidence spacing and no measurement, two capable models computed widths from their own pixel estimates and did worse than their prior-anchored guesses. The specification's `measured` profile, not `core`, should be the default for consumers that ask quantitative questions, and a producer that can only supply low-confidence spacing should say so in the reference file, as template 0.2 does.

Where the main result does not separate the models, three secondary tasks do. The flip check is the cleanest: with the true and a mirrored render each shown once, eight models answered "agree" every time, which is not perception failure but the absence of a check. Gemini 3.8 Flash performed the check on 98 of 100 images, GPT-5.6 Terra on 75 and GLM-5.3 Flash on 61, so the ability exists and is unevenly distributed; a consumer that needs it must test for it. The mark-side task reproduces the laterality failure of small models in the presence of printed labels [2], and the misleading-text task reproduces the adoption rates of MC-CXR [3] and adds a second finding: a cautioned, labelled delivery reduces adoption by amounts that range from nothing to nearly everything depending on the model. The protocol's answer is not to trust the caution but to withhold the text by default, which is what a data standard can guarantee and a prompt cannot.

The scintigraphy results generalise the pattern to a second modality with different physics and a different convention. The facts a scintigram needs, modality, the mirrored posterior display, the absence of a calibrated scale, the non-comparability of counts, were supplied by the package and used by every model; the intensity reading against the stated orientation was not, and the sample of eight asymmetric scans is too small to say more than that.

Two design choices deserve comment. First, the benchmark's ground truth for the measurement tasks is the package's own tool output, validated at Tier 1 with one cross-tool check, and the CTR is known to be biased high because the lung-field union underestimates the thoracic width. The benchmark therefore measures whether a model uses the package's measurement, and the paper does not claim that the measurement is clinically correct; the Tier 2 comparison against CheXmask [28] and the expert readings are the next step, and the protocol's validation status field exists so that a consumer can tell the difference. Second, the reference file and the benchmark were written by the same project. The tasks were designed to be unanswerable from the file verbatim, and three of them (mark side, flip check, hotter side) were failed by most models with the file in hand, but the risk of a benchmark tuned to its own format is real and is the reason the harness, packages and replies are released for others to extend.

Finally, the specification changed during the study, and the change is recorded as a proposal with its evidence. We think this is the maintenance model such a protocol needs: every change to what the model is told is a hypothesis about model behaviour, and the benchmark is where it is tested before it ships.

## 8. Limitations

Each cell is a single reply; no run-to-run reliability was measured, and the cloud models were not pinned to a version. The two flip-check items per image are not independent, and the binomial tests treat them as if they were. The measurement truth is tool-derived and validated at Tier 1 only; the left-edge truth on VinDr-CXR rests on the converter's inferred orientation and a 1,000-image laterality check, since the headers carry no orientation. The three datasets are single-source public collections, two-dimensional, and the NIH images passed through an 8-bit non-DICOM path; CT and MR are out of scope for this version. Nine of eleven models reached 100 % on the primary endpoint, so the benchmark cannot rank them there. The hotter-side task has eight items. The wording ablation of Section 6.6 is a 20-image pilot and its effect was smaller on the full set. The analysis plan is post hoc. The reference file, the tasks and the scorer were authored by the same project that built the protocol.

## 9. Conclusion

A medical image can be made to describe itself to a model. A schema-validated manifest, a fixed-template reference file with assertion levels, correct renders and tool-computed measurements took eleven vision-language models from 17–74 % to 99–100 % on questions of orientation, scale and calibrated measurement, and removed most of the difference between them. What the package cannot do is make a model look: a mirrored render, a wrong label and an asymmetric tracer distribution were still missed by most models with every fact in hand, and those tasks now separate models that the main result no longer can. The specification, converter, benchmark, package manifests and all 60,483 replies are released so that the next change to the protocol can be tested the same way.
